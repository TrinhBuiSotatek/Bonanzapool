# US-EXBOT-004: Close ExBot and redeem funds

## Story Statement

As a **USDC Investor who wants to exit their ExBot position**,
I want to **close my ExBot and receive my USDC back**,
So that **I can fully exit the strategy and retrieve my capital without manual on-chain steps**.

**INVEST check:** I✓ N✓ V✓ E✓ S✓ T✓

## Acceptance Criteria

```gherkin
AC-EXBOT-004-1: Happy path — user_close flow completes within SLA
  Given the investor has an active ExBot
  When the investor clicks "Close Bot" on BNZP UI and confirms "close everything, return USDC"
  Then the system enqueues a user_close job (highest priority) via Operator API
    And the Operator closes the HL hedge via Signing Lambda (Agent CMK) within 5 minutes of the close request
    And the HL short is fully closed and reconciled at size = 0
    And the Operator calls BnzaExVault.vaultClose(dest=USER) via Master Signing Lambda to liquidate the LP
    And the LP-portion USDC is transferred to the investor's wallet on-chain by the Operator
    And the HL-portion USDC is sent to the investor after hedge close is confirmed
    And the bot lifecycle_state transitions to 'closed'

AC-EXBOT-004-2: Edge case — hedge close takes longer than SLA
  Given a user_close hedge close job is processing
  When 5 minutes elapse from the Operator close request without confirmed hedge closure
  Then the system escalates the job to admin alert with "user_close SLA breached for bot {id}"
    And the LP-portion repayment has NOT yet occurred (hedge must close before LP close)
    And the admin receives escalation to resolve the hedge position manually

AC-EXBOT-004-3: Negative path — hedge close fails, LP close blocked
  Given the user_close Worker retries HL hedge close 3 times within the Lambda invocation
  When all 3 retries fail due to HL API unavailability
  Then the system marks the close_operations record as 'residual_hl_liability'
    And notifies admin with exact bot_id, hedge size, and estimated USD value outstanding
    And LP close does NOT proceed (LP-portion USDC is NOT transferred until hedge is resolved)
```

## Notes

UI must clearly distinguish: "Close Bot (close everything, return USDC)" from "Pause Bot (hedge is maintained)". The close is fully Operator-executed — user only clicks confirm on BNZP UI, no on-chain wallet signing required. Two close triggers exist: user_close (user-initiated via UI, LP-first) vs bot_safe_close (system-initiated, hedge-first). This story covers only user_close. Bot_safe_close is covered in US-EXBOT-009.
